# Move to Linux + first push

## Did
- Copied the repo from Windows to the Linux dev machine with `scp -r` (corporate Zscaler blocked personal pushes from the laptop).
- Created a **repo-scoped deploy key** `~/.ssh/yapp_deploy_key` (ed25519, passphrase) and added the public half in GitHub → repo Settings → Deploy keys, **Allow write access** ticked (done from the Windows VM 10.20.40.111 over RDP).
- Wired it in for this repo only: `git config --local core.sshCommand "ssh -i ~/.ssh/yapp_deploy_key -o IdentitiesOnly=yes"`; remote switched to `git@github.com:Shankarr-18/yapp.git`.
- First SSH connection: checked GitHub's host key fingerprint before answering `yes` → saved in `~/.ssh/known_hosts`.
- Account changed Shank8r → **Shankarr-18**; set local identity `Shankarr-18 <shankarhm1874@gmail.com>` and rewrote all 3 unpushed commits with `git rebase --root --exec "git commit --amend --no-edit --reset-author"`.
- `git push -u origin main` — first push succeeded.
- Found port 8000 already used by another team's container (`docker ps`, `ss -tlnp`) → yapp uses host port **8500** on this machine.

## Learned
- Deploy key = SSH key bound to **one repo** (not to a user). Smaller blast radius than a personal key — ideal on a shared account.
- Host key verification protects *me* from talking to a fake GitHub (MITM); my key protects GitHub from a fake *me*.
- `core.sshCommand` picks the key per repo without editing the shared `~/.ssh/config`.
- Rewriting history is safe only **before** pushing; after pushing it needs a force-push and breaks others' clones.
- `docker ps` PORTS `0.0.0.0:8000->8000/tcp` = host port 8000 on all interfaces → container port 8000.
- Bind `127.0.0.1` = same machine only; `0.0.0.0` = every interface (reachable from the network).

## Decisions
- Auth on the shared Linux account: deploy key + passphrase, not a personal SSH key or PAT.
- yapp host port on this machine: 8500. Inside containers the app still listens on 8000.
